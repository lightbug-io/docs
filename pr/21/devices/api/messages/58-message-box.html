Replace or clear the cached message #

Every accepted SET updates the cache, writes it to persistent storage when enabled, and publishes to current subscribers, even for identical bytes. SET does not change the selected subscription format.

Target Message Box-enabled firmware

SET version 2

Message Version 2 and field 129 are required. The device calculates the payload CRC; the outer message-frame CRC protects the SET request itself.

Tracking-session uploads #

A separate device-to-server context, not a GET response or subscription update. Tracking-session messages always use Message Version 2. Field 129 may carry independent Transmit Now upload data, not the cached down-synced payload.

Target Message Box-enabled firmware

Device upload (MT58)

When Message Box support is enabled, field 2 reports the cached-message CRC, including 0 for an empty cache. Independent upload bytes in field 129 do not form part of that cached-message CRC.

Shared behavior

Payload CRC and frame CRC are different

The device calculates and stores CRC-16/XMODEM of the cached payload: polynomial 0x1021, initial value 0x0000, no input or output reflection, final XOR 0x0000. The outer message-frame CRC protects the complete frame. The 16-bit payload CRC can collide for different payloads; changed bytes are still applied even when their CRC matches the previous CRC.

Firmware support

Unsupported products return Not Supported (Status header 4, code 7). The CRC field is currently implemented only on Viper devices. These generated examples illustrate supported behavior, not captures or claims of support on other targets.
